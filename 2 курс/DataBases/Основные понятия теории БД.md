**Данные** - это информация, представленная в определённом виде, может быть в хаотичном или в упорядоченном формате.

**База данных** (БД) - это совокупность данных, организованных по определённым правилам, предусматривающая хранение, описание, манипулирование и удаление данных.

**СУБД** (Система управления базы данных) - это целый комплекс программ, позволяющий создавать базу данных и манипунилировать данными.

## Популярные СУБД

1. Microsoft SQL Server (MS SQL Server)
2. MySQL
3. Oracle
4. PostgreSQL
5. MongoDB

Для работы с БД используется язык запросов SQL.

SQL - это язык, предназначенный для работы с БД.

## Особенности SQL

1. Не является самостоятельным языком программирования.
2. Имеет чёткую структуру.
3. Близок к естественному английскому языку.
4. Имеет декларативный характер. При написании кода пользователь указывает, что хочет получить, а система сама определяет, как выполнить задачу.
5. В нём нет циклов, ветвей и других привычных процедурных конструкций.

## Список диалектов языка SQL

1. T-SQL (TransactSQL) - используется в MS SQL Server
2. PL/SQL (Procefural SQL) - используется в Oracle
3. SQL/PSM - используется в MySQL
4. PLpg/SQL - используется в PostgreSQL
5. Jet SQL - используется в Microsoft Access

## Технологии работы БД

### Централизованная архитектура
когда всё находится на одном ПК.

Бугхалтер сам вводит данные в компьютер - сотрудникам ничего не требуется делать.

#### Преимущества
1. Очень легко управлять, всё находится в одном месте
2. Максимальная безопасность
#### Недостатки
1. Колоссальная нагрузка на компьтер
2. Если сломается компьютер - будет нерабочая БД

![[БД.png|700]]
### Архитектура файлов сервера
Архитектура File-Server - участвуют персональные компьютеры и серверы. Сервер не участвует в обработке своих данных, он их только хранит.

#### Преимущества
1. Дёшево и просто настроить. Просто сделать общий доступ
#### Недостатки
1. Огромный трафик
2. Конфликты одновременного использования

![[File-system.png|670]]

### Архитектура Клиент-Сервер

#### Преимущества
1. Малая нагрузка на сеть
2. Масштабируемость
3. Централизованное управление
4. Повышенная безопасность
5. Эффективная совместная работа

#### Недостатки
1. Зависимость от сервера
2. Зависимость от сети
3. Задержка из-за удалённого сервера



![[Drawing 2026-09-08 13.29.03.excalidraw.png]]

### Трёхзвенная (трёхуровневая/многоуровневая) архитектура
Использует архитектуру клиент-сервер, но добавляет промежуточную инстанцию.

#### Плюсы
1. Гибкость
2. Масштабируемость
3. Снижение требований к ПК клиента
4. Повышенная отказоустойчивость

#### Минусы
1. Очень сложная разработка
2. Задержка ответа по сети
3. Большие затраты на обслуживание

## Модели БД

Это способ структурирования данных и описания взаимосвязей между ними.

### Файловая модель
Состоит из поля и файлов записи. Нет связей между файлами

### Иерархическая модель
Между данными появилась связь: родитель-потомок.
Модель представляется в виде иерархии.
У связи родитель-потомок только 1 родитель.

### Сетевая модель
Представляет собой развитие иерархической модели. Модель позволяет описывать более сложные виды взаимосвязей между данными. Появляется связь многое ко многому.

### Реляционная модель
Самая популярная. Данные представляются в виде таблиц. В этой модели присутствуют связи 1 к 1, 1 к многому и много ко многому


### Гибридная (объектно-реляционная) модель
Объединяет другие типы моделей в одну.
